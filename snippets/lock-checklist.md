# 잠금 화면(지문 로그인) 적용 체크리스트

위에서부터 차례로 하고, 한 단계 끝날 때마다 확인한다. 자세한 설명은 `DESIGN.md` 14장.
**지문창은 봇이 볼 수 없다. 5~7단계와 확인 항목은 반드시 폰에서 직접 본다.**

## 1. 잠금 화면 틀
- [ ] `lock.html`을 앱 화면(`#app`) 앞에 복사하고, 제목의 "앱 이름"을 바꾼다.
- [ ] `lock.css`를 복사한다. (`tokens.css`가 먼저 있어야 한다.)
- [ ] 배경은 `F5F6FB` 단색 그대로. `theme-color`, manifest 색과 같은지 확인(상태바가 일반 화면과 같은 색).
- [ ] 앱 화면(`#app`)은 처음에 `hidden`으로 시작한다.

## 2. 지문 등록
- [ ] 설정 시트에 "지문 등록" 줄을 넣는다. 등록됨이면 "지문 등록됨 (탭하여 해제)"로 바꿔 보여준다.
- [ ] 등록 전에 PIN을 한 번 더 확인한다. 지문을 PIN 없이 단독으로 쓰지 않는다.
- [ ] 해제하면 등록 정보를 지우고 "지문 등록이 해제되었습니다"를 알린다.

## 3. 자동 실행
- [ ] `lock.js`를 복사하고 "앱이 연결하는 자리" 3곳(PIN 검증, 지문 등록 확인, 지문 인증)에 앱의 함수를 연결한다.
- [ ] 앱을 열면 지문창이 바로 뜬다. 지문 미등록 기기는 아무것도 안 뜨고 PIN만 보인다.
- [ ] 자동 실행이 막혀도 오류 문구가 없다.

## 4. 취소 시 PIN
- [ ] 지문창을 취소하거나 실패하면 PIN 화면이 그대로 남고, 지문창이 저절로 다시 뜨지 않는다.
- [ ] 지문 아이콘을 누르면 다시 지문창이 뜬다.
- [ ] 아이콘을 빠르게 여러 번 눌러도 지문창이 겹쳐 뜨지 않는다.

## 5. --fp-top 맞추기 (폰 사진)
- [ ] 폰에서 시스템 지문창이 뜬 상태로 사진을 찍는다. (개인정보가 보이지 않게)
- [ ] 화면 높이 대비 지문 원 중심의 위치(%)를 재서 `lock.css`의 `--fp-top` 한 값만 바꾼다. 시작값은 `80dvh`.
- [ ] 우리 지문 아이콘이 시스템 지문 원 바로 뒤에 겹치는지 다시 사진으로 확인한다. (재는 방법: DESIGN.md 14장)

## 6. PC 키보드
- [ ] 윗줄 숫자, 숫자패드, Backspace가 모두 되는지.
- [ ] 잠금이 풀린 뒤에는 키 입력을 가로채지 않는지(다른 입력칸에 숫자가 써지는지).

## 7. 확인 항목
- [ ] PIN을 틀리면 점이 흔들리고 문구가 나왔다가 약 1.4초 뒤 원래 문구로 돌아온다.
- [ ] 문구가 연한 배경에서 읽힌다.
- [ ] 높이가 낮은 화면(700px 이하)에서 숫자판이 지문 아이콘과 겹치지 않는다.
- [ ] 홈 화면 앱(설치한 앱)과 브라우저 둘 다에서 지문창이 뜬다.
- [ ] 지문 인식 방식, PIN 검증, 암호화 코드는 화면 작업 중에 고치지 않았다.
- [ ] 화면 캡처에 ID·비밀번호 같은 개인정보가 보이지 않는다.
- [ ] 배포 때 `sw.js` 캐시 번호 +1, 설정 시트 버전 표시도 올렸다.
